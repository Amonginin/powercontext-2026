# 上下文召回助手（PowerContext）

## 适用场景

对话或工作流已经很长，用户的当前提问依赖更早的信息：

- 「我之前说过我喜欢什么风格的报告？」
- 「上次我们定下的结论是什么？」
- 「继续上次那个任务，做到哪了？」
- 「我配置过哪些选项？」
- 「上次那个 PDF 找到证据了吗？」

不适用：与历史无关的通用知识问答（直接回答即可，不必检索）。

## 前置条件

需要一个可访问的 PowerContext 实例。其上下文查询接口可通过以下任一方式接入：

- **HTTP API**：`POST {base_url}/api/v1/context/search`，请求体含 `query` / `memory_kind` / `budget` / `scope`
- **MCP 工具**：`search_context` 之类的工具，入参同上
- **Python SDK**：`from powercontext import ContextClient`

具体接口路径与字段名以你的实例版本为准（PowerContext 提供 HTTP API、MCP 与 Python SDK 三种接入方式）。
详见 <https://powercontext.oceanbase.io/zh/docs/develop/interfaces/>。

## 执行流程

### 第 1 步：判断是否真的需要检索

只有当当前问题**依赖历史信息**时才走下面的流程。
如果问题可以仅凭当前对话回答，直接回答，不要为了「显得在用工具」而无谓检索——多余的检索会拖慢响应并引入噪声。

### 第 2 步：把问题拆成检索请求

从用户问题里抽出：

| 字段 | 说明 | 例 |
|---|---|---|
| `query` | 用于语义匹配的检索语句，用用户的原话或其摘要 | 「报告风格偏好」 |
| `memory_kind` | 记忆类别：`preference` / `task` / `fact` / `conversation` | 「我的偏好」→ `preference` |
| `budget` | 允许取回的条目数上限 | 默认 5，用户说「全都」时放宽到 20 |
| `scope` | 限定范围，如某次会话、某个项目、某个用户 | 用户说「上次那个任务」→ 取最近的会话 |

**关键**：写 `query` 时用**语义描述**而不是原句照抄。
检索是向量匹配，描述「用户偏好的报告风格」比「我之前说过我喜欢什么风格的报告」匹配效果好得多。

### 第 3 步：调用 PowerContext 取回证据

用第 2 步的四个字段发起查询。

- 返回为空 → 进入第 5 步的「没有找到」分支。
- 返回多条 → 进入第 4 步排序。

### 第 4 步：核验与回答

**先核验再回答**，这是本题的核心要求：

1. 对每条取回的条目，**确认它确实来自检索结果**，不能引入记忆里的臆测内容。
2. 如果多条结果互相矛盾，**说明存在多个版本**，并按更新时间指出哪个是较新的。
3. **不要把未核实的内容当作事实陈述**。取回的条目就是来源，回答里要能追溯到它。
4. 如果取回的内容不足以回答问题，如实说明「已找到的记录只覆盖了 X 部分，Y 没有记录」，
   **不要用通用知识补齐缺口并伪装成历史信息**。

回答里带上来源标识，例如：

```
根据检索到的记录（来源：记忆条目 #a3f2，更新于 2026-10-28）：
你偏好简洁结论优先、附一张对比表的报告风格，并且要求表格带排序列。
```

### 第 5 步：没有找到时的处理

检索为空**不要编造**。按下面的顺序处理：

1. 明确说明「没有检索到相关记录」。
2. 如果可能，用**更宽的说法**再检索一次（例如把 `query` 从具体描述放宽到上位概念）。
3. 仍为空 → 告诉用户没有历史记录，请其直接说明，或提供可检索的信息来源。

## 与任务状态复用的配合

当问题涉及**任务进展**（「上次做到哪了」）时，除了语义检索，
还应读取该任务保存的**状态记录**：已完成事项、待办事项、已有验证结果。

这部分状态是结构化存储的，直接读取比向量检索更准确。
回答时按「已完成 / 待办 / 已验证」三段呈现，并注明状态来自哪个任务。

## 硬性约束

1. **所有事实性内容必须来自检索结果或状态记录**，不得来自推测。
2. 检索为空时**如实说明**，不编造历史内容。
3. 取回内容不足以回答时，**说明缺口**，不用通用知识伪装成历史信息。
4. 回答中**标明来源**（条目标识或更新时间）。
5. 矛盾信息要**同时呈现**并指出较新版本，不擅自二选一。
6. 状态与检索**都要读**：任务类问题不能只做语义检索而漏掉结构化状态。

## 使用示例

```
用户：我之前说过我偏好什么样的报告格式？

助手：（检索 preference 类记忆，budget=5）
根据检索到的记录（来源：记忆条目 #a3f2，更新于 2026-10-28）：
你偏好简洁结论优先、附一张对比表的报告风格，并且要求表格带排序列。
```

```
用户：继续上次那个 PDF 证据检索的任务，做到哪一步了？

助手：（先检索 task 类记忆，再读取该任务的状态记录）
上次「财报 PDF 证据页检索」任务的状态：
  已完成：PDF 解析与页面文本抽取（120 页）、按行项目反查页码
  待办：补充跨页证据合并；用 nDCG@10 复核召回质量
  已验证：单页命中 38/40，跨页证据 6 条
（来源：任务 #t-8821，状态更新于 2026-11-10）
```

```
用户：帮我总结一下我们讨论过的数据库索引优化方案。

助手：（检索无结果）
没有检索到与「索引优化方案」相关的历史记录。
当前会话里没有这部分内容，请直接说明要点，或告诉我相关文档/会话的范围，我再检索一次。
```
