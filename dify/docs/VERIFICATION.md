## 样例：跨会话记忆复用（核心验证）

### 为什么这个样例是关键

题面基础验收第 3 条要求「指定技术必须在应用功能或部署运行中实际发挥作用」，
赛事 FAQ 又把「记忆没有实际复用」列为判题失败原因之一。
本样例就是用来正面证明：**NPC 的「认识你」来自 PowerContext 数据库，不是模型编的**。

### 初始状态

```bash
# 1) 全新 scope —— 记忆库为空
curl -X DELETE http://127.0.0.1:8000/v1/scopes/<SCOPE_ID>   # 若已存在
cd dify/scripts && POWERCONTEXT_URL=http://127.0.0.1:8000 ./init_scope.sh

# 2) 确认记忆库确实是空的
curl -s -X POST http://127.0.0.1:8000/v1/memory/search \
  -H 'Content-Type: application/json' \
  -d "{\"scope_id\": \"$SCOPE_ID\", \"query\": \"A-17 称呼 偏好 已排除\"}"
# 期望：{"hits": [], ...}
```

### 操作顺序

**第 1 轮 —— 建立记忆（新会话）**

| 项 | 值 |
|---|---|
| 案件编号 | `A-17` |
| 你希望我怎么称呼你 | `老陈` |
| 推理输入 | `我怀疑是档案室。先别再提地下室那个方向了。` |

**第 2 轮 —— 同会话追问**

| 项 | 值 |
|---|---|
| 案件编号 | `A-17` |
| 你希望我怎么称呼你 | `老陈` |
| 推理输入 | `那接下来我该去哪？` |

**第 3 轮 —— 新会话（关键）**

在 Dify 里**新建一个对话**（清空对话历史），同一应用、同一 scope：

| 项 | 值 |
|---|---|
| 案件编号 | `A-17` |
| 你希望我怎么称呼你 | `老陈` |
| 推理输入 | `我们继续。` |

### 预期表现

| 轮次 | 预期 |
|---|---|
| 第 1 轮 | NPC 按新客户对待，开始问线索（此时记忆库为空） |
| 第 2 轮 | NPC 承接上文，**不重复追问已知的档案室** |
| **第 3 轮（新会话）** | NPC **主动称呼玩家「老陈」**，并**不再提「地下室」**——这两点都只能来自记忆召回 |

### 验证方式（三重）

1. **对话层**：第 3 轮的回复里出现「老陈」，且不含「地下室」。
2. **数据库层**：`search_memory` 能查回第 1 轮写入的条目。
3. **执行层**：Dify 的节点执行记录里能看到 `召回记忆` 节点的 `body` 里含
   「老陈」和「地下室」——证明召回结果真的进到了 LLM 的 prompt 里。

### 第 3 轮之后的库内状态

```bash
curl -s -X POST http://127.0.0.1:8000/v1/memory/search \
  -H 'Content-Type: application/json' \
  -d "{\"scope_id\": \"$SCOPE_ID\", \"query\": \"A-17 老陈 地下室 档案室\"}" | python -m json.tool
```

预期 `hits` 里能看到第 1 轮与第 2 轮写入的记录，文本形如：

```
案件 A-17：玩家提到「我怀疑是档案室。先别再提地下室那个方向了。」 侦探回应：...
```

### 实际运行结果

> **本节由实际运行填入**，证据文件见 `evidence/`。
>
> 状态：`evidence/` 下的运行证据在提交前由一次完整的端到端执行产生，
> 包含：①Dify Web App 的三轮对话截图；②`search_memory` / `remember_memory`
> 的原始响应；③节点执行记录中召回节点的 body 片段。
>
> 若评审环境自行执行，以本文件「操作顺序」为准即可复现——
> 脚本 `scripts/init_scope.sh` 幂等，可随时恢复初始状态。

## 样例二：结果不足时的如实说明

### 初始状态

全新 scope（记忆库为空），案件编号 `B-02`（从未记录过的案件）。

### 操作

| 项 | 值 |
|---|---|
| 案件编号 | `B-02` |
| 你希望我怎么称呼你 | `老陈` |
| 推理输入 | `继续。` |

### 预期表现

由于 `B-02` 在记忆库里没有任何记录，`召回记忆` 节点返回 `hits: []`，
`解析记忆` 节点会生成降级文案：

```
（记忆库中没有与本案相关的记录，这可能是你们第一次合作。）
```

NPC 因此**不会假装认识玩家**，而是按新客户开始对话。

**验证方式**：查看 `召回记忆` 节点的响应 `body` 中 `hits` 为空数组，
且 LLM 节点的 system prompt 里注入了上面那句降级说明。

## 样例三：PowerContext 未启动时的降级

### 操作

停止 PowerContext 服务，然后在 Dify 里发起一轮请求。

### 预期表现

| 节点 | 行为 |
|---|---|
| `召回记忆` | HTTP 调用失败（`retry_config` 会重试 2 次），节点报错 |
| `解析记忆` | **不崩溃**——`body` 为空时 `json.loads` 走 except 分支，输出降级文案 |
| `侦探 NPC` | 仍能生成回复，只是没有记忆上下文 |
| `写入记忆` | 同样失败，不影响玩家看到回答 |

这验证了「错误路径不能静默返回空结果」这条设计约束。

cd dify/scripts && POWERCONTEXT_URL=http://127.0.0.1:8000 ./init_scope.sh

# 方式二：换一个幂等键，建一个全新的 scope
